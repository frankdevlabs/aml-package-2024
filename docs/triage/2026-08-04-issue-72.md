  identical requests flip between `200` (valid RSS, real `<item>`s) and `500` ("Er is iets mis
  gegaan"). Isolation testing showed the 500 is not deterministic per clause: the same
  `w.publicatienaam` filter returned 200 on one call and 500 on the next. So:
  - The URL is **not** stale or moved — it is the correct query and returns valid data when the
    backend cooperates.
  - The `q=` CQL syntax is **valid** (malformed queries on this host return HTTP 400, not 500;
    a bare-index probe confirmed the 400/500 split).
  - The failure is a **server-side backend/load-balancer intermittency** on
    officielebekendmakingen.nl, not a tracker or config problem. The cron's single
    retry-after-backoff happened to hit two 500s in a row.

  Correct handling: keep the source, do **not** auto-pause, and record the intermittent-500
  pattern + retry guidance in the T1-09 `notes` (mirroring the T1-08 Akamai note) so a future
  single-run 500 is not mis-read as a dead feed. If it fails on **consecutive weekly runs**
  (next: week of 2026-08-10), revisit for auto-pause.
